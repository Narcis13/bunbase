# Milestone v0.3: Custom API Endpoints

**Status:** ✅ SHIPPED 2026-01-31
**Phases:** 14-17
**Total Plans:** 8

## Overview

BunBase v0.3 enables developers to add custom business logic endpoints beyond auto-generated CRUD. Starting with a robust error and context foundation, we built a file-based route system that discovers handlers at build time, integrates them into the server, and embeds them in the compiled binary.

## Phases

### Phase 14: Foundation (Context & Errors)

**Goal**: Establish the error system and RouteContext interface that all custom routes will use
**Depends on**: Nothing (first phase of v0.3)
**Plans**: 2 plans

Plans:
- [x] 14-01: ApiError class hierarchy and handleApiError utility
- [x] 14-02: RouteContext interface and createRouteContext factory

**Details:**
- Created ApiError base class with 6 HTTP error subclasses (BadRequest, Unauthorized, Forbidden, NotFound, Conflict, ValidationFailed)
- PocketBase-compatible error format `{ code, message, data }`
- Dev/prod error handling (hide internal details in production)
- RouteContext interface exposing db, records, auth, realtime, files, hooks
- RecordsAPI wrapping hook-aware CRUD operations
- AuthAPI with buildContext, optionalUser, requireAdmin

### Phase 15: Route Loading

**Goal**: Discover and load custom route handlers from routes/ directory with build-time manifest generation
**Depends on**: Phase 14
**Plans**: 2 plans

Plans:
- [x] 15-01: Route discovery utilities with TDD (filePathToRoutePath, parseRouteExports)
- [x] 15-02: Build script and manifest generation (scripts/build-routes.ts)

**Details:**
- TypeScript Compiler API for robust export detection (handles comments, strings)
- File path to route path conversion with [param] to :param
- Lowercase method export warnings (get → "Use uppercase GET")
- Build-time manifest generation with static imports
- Example routes: health.ts, stats.ts

### Phase 16: Server Integration

**Goal**: Wire custom routes into BunBase server with context injection and error handling
**Depends on**: Phase 15
**Plans**: 2 plans

Plans:
- [x] 16-01: Server accepts customRoutes parameter, merges into routes, adds dev mode config
- [x] 16-02: CLI loads routes at startup, creates managers, logs in dev mode

**Details:**
- Custom routes merged after system routes, before admin routes
- Development mode with HMR and browser console streaming
- CLI creates HookManager/RealtimeManager and shares with buildCustomRoutes and startServer
- Route logging in development mode

### Phase 17: Build Pipeline & Testing

**Goal**: Ensure custom routes are embedded in binary and work correctly in both development and production
**Depends on**: Phase 16
**Plans**: 2 plans

Plans:
- [x] 17-01: Route manifest generation tests and development mode integration tests
- [x] 17-02: Compiled binary integration tests and test scripts

**Details:**
- tests/routes.test.ts for manifest generation and dev mode
- tests/binary.test.ts for compiled binary verification
- Test scripts in package.json (test, test:routes, test:binary)
- Port isolation (8097 for routes, 8099 for binary tests)

## Milestone Summary

**Key Decisions:**
- PocketBase error format for API compatibility
- TypeScript Compiler API over regex for export parsing
- Routes merge order: system → custom → admin
- Generated manifest gitignored (regenerated at build time)
- Dual env detection (NODE_ENV + BUNBASE_DEV)

**Issues Resolved:**
- Root index file edge case in route discovery
- TypeScript strict mode in tests (non-null assertions)

**Issues Deferred:**
- Pre-existing test failures in src/api/*.test.ts (collection name collisions)

**Technical Debt Incurred:**
- None specific to this milestone
